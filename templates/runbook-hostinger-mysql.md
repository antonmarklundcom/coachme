## Step 2 — Enable Remote MySQL for your machine (~2 min)

1. hPanel → **Databases → Remote MySQL**.
2. Add your current public IP (get it from https://api.ipify.org).
3. Note the remote host shown on that page — `srv####.hstgr.io`. It is **not** the
   `localhost` the deployed app uses. This runbook calls it `<REMOTE_HOST>`.

> Home ISPs rotate IPs after a router restart. `Access denied for user
> '{{db_user}}'@'<some ip>'` later means exactly this — re-add the new IP here.

## If it goes wrong

| Symptom | Cause | Fix |
|---|---|---|
| `Access denied for user '{{db_user}}'@'…'` | your public IP changed | re-add it in Remote MySQL (step 2) |
| `ECONNREFUSED` on a seed script, migration was fine | script's `DATABASE_URL` is undefined | export it in the shell (step 4) |
| Live site: generic "Application error" / `Digest:` | stale `DATABASE_URL` in hPanel after a password change | update the env var, then **redeploy** |
| `ERR_INVALID_URL`, error `input` contains `DATABASE_URL=` | key pasted into the value field | paste the raw value only |
| Host `srv####.hstgr.io` refuses but phpMyAdmin logs in fine | DNS/IPv6 flakiness | use the IPv4 address shown on the Remote MySQL page instead |
