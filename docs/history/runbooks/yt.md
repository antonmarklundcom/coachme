# Runbook — `yt` (Hostinger MySQL + Drizzle)

> Generated by `src/runbook.js` from the repo's own stack. **Placeholders only —
> never paste a real password into this file.** Keep secrets in your password
> manager and in local `.env` files.
>
> `yt-intel` · 60% done · tier `experiment` · ~20 min

## Step 1 — Create the database and user (hPanel, ~3 min)

1. hPanel → **Databases → Management**.
2. **Database name:** type `yt`. hPanel prefixes it with your account id, so
   the real name becomes `<PREFIX>_yt` — write the full name down, you need it in step 3.
3. **Database user:** type `yt` (same prefix rule → `<PREFIX>_yt`).
4. **Password:** generate a strong one in your password manager, save it there as
   *"yt — Hostinger MySQL"*. This runbook calls it `<PASTE_DB_PASSWORD>`.
5. Create. Confirm the DB shows up in the list before moving on.

> If this app is **already deployed**, open hPanel → Environment Variables and read the
> existing `DATABASE_URL` **before** you change any password. Changing a live app's DB
> password without updating that variable takes the site down with a generic
> "Application error" page and no useful log line.

## Step 2 — Enable Remote MySQL for your machine (~2 min)

1. hPanel → **Databases → Remote MySQL**.
2. Add your current public IP (get it from https://api.ipify.org).
3. Note the remote host shown on that page — `srv####.hstgr.io`. It is **not** the
   `localhost` the deployed app uses. This runbook calls it `<REMOTE_HOST>`.

> Home ISPs rotate IPs after a router restart. `Access denied for user
> '<PREFIX>_yt'@'<some ip>'` later means exactly this — re-add the new IP here.

## Step 3 — Point your local checkout at it (~2 min)

```bash
cd yt
npm ci
```

Create `.env` (or `.env.local`) with:

```
DATABASE_URL=mysql://<PREFIX>_yt:<PASTE_DB_PASSWORD>@<REMOTE_HOST>:3306/<PREFIX>_yt
ADMIN_EMAIL=<PASTE_ADMIN_EMAIL>
SESSION_SECRET=<PASTE_SESSION_SECRET>
```

`.env.example` lists 8 further variables (API keys, payment,
mail). They are **not** needed to create and migrate the database — leave them for
the launch step so this sitting stays short.

> On Windows PowerShell, never write `.env` with `>` redirection — it produces UTF-16
> and the dotenv parser silently reads nothing. Use:
> `Set-Content -Path .env -Value 'DATABASE_URL=...' -Encoding utf8`

## Step 4 — Create the schema (~5 min)

```bash
npm run db:migrate
```

Then seed. Plain `tsx` scripts do **not** auto-load `.env` the way `drizzle-kit` does,
so export the variable for the shell session first:

```bash
export DATABASE_URL="mysql://<PREFIX>_yt:<PASTE_DB_PASSWORD>@<REMOTE_HOST>:3306/<PREFIX>_yt"
npm run db:seed
```

```powershell
# PowerShell equivalent — stays set for the rest of the window
$env:DATABASE_URL = "mysql://<PREFIX>_yt:<PASTE_DB_PASSWORD>@<REMOTE_HOST>:3306/<PREFIX>_yt"
npm run db:seed
```

> `ECONNREFUSED` on the seed right after a **successful** migration always means the
> script's `DATABASE_URL` is undefined and mysql2 fell back to localhost — not that
> the database is down.

## Step 5 — Give the deployed app its variables (~3 min)

hPanel → the `yt` Node.js app → **Environment Variables**:

```
DATABASE_URL=mysql://<PREFIX>_yt:<PASTE_DB_PASSWORD>@localhost:3306/<PREFIX>_yt
ADMIN_EMAIL=<PASTE_ADMIN_EMAIL>
SESSION_SECRET=<PASTE_SESSION_SECRET>
```

- The live app uses **`localhost`**, not the remote host from step 2.
- Paste only the *value* into the value field. If a build error shows
  `input: 'DATABASE_URL=mysql://...'`, the whole `KEY=value` string went into the value box.
- Env var changes need a **redeploy**, not just a restart.

## Step 6 — Verify (~2 min)

```bash
npm run db:check
```

Then open the deployed URL and create one real record. If the page renders and the
record persists, `yt` is unblocked — tick it on the dashboard.

## If it goes wrong

| Symptom | Cause | Fix |
|---|---|---|
| `Access denied for user '<PREFIX>_yt'@'…'` | your public IP changed | re-add it in Remote MySQL (step 2) |
| `ECONNREFUSED` on a seed script, migration was fine | script's `DATABASE_URL` is undefined | export it in the shell (step 4) |
| Live site: generic "Application error" / `Digest:` | stale `DATABASE_URL` in hPanel after a password change | update the env var, then **redeploy** |
| `ERR_INVALID_URL`, error `input` contains `DATABASE_URL=` | key pasted into the value field | paste the raw value only |
| Host `srv####.hstgr.io` refuses but phpMyAdmin logs in fine | DNS/IPv6 flakiness | use the IPv4 address shown on the Remote MySQL page instead |
