## Built

- `lib/github/write.ts` — the whole outbound capability: `putPromptFile`,
  `createIssue`, `mergePull`, and nothing else. Path derived from the slug, not
  accepted; merge limited to `coachme/`, `claude/`, `codex/` heads, open,
  conflict-free and green.
- `lib/github/checks.ts` — pure PR-state reading; `lib/github/probe.ts` — the
  token probe that sets `settings.github_write_ok`.
- `lib/dispatch/run.ts` — approve-gated dispatch to `repo-file`, `issue` or
  `copy`, with the audit row; `lib/dispatch/merge.ts` — the Merge button.
- `lib/scan/link.ts` + `lib/scan/run.ts` — PR tracking (D-G), stage raising from
  fetched evidence, the generator inside the scan, and one write-access probe
  per run. New `ScanRunResult` fields: `tracked`, `staged`, `proposed`.
- `app/api/dispatch`, `app/api/merge`, `app/api/generate` — owner-gated, POST
  only, added to `proxy.ts`'s `CLOSED_WITHOUT_SECRET`.
- `lib/nudge/ladder.ts` — two rungs on top (`merge-prs`, `owner-step`) and the
  digest line; `migrations/0004_digest_rungs.sql` widens the `nudges.type` CHECK.
- `lib/report/weekly.ts` + the Monday branch of `runNudge` → `settings.weekly_report`.
- Tests: `tests/github-write.test.ts` (17), `tests/dispatch.test.ts` (28). Suite:
  237 vitest + 130 legacy.

## Decisions

- **An unreachable checks API is never green.** Written after the first version
  of the merge test passed while the CI endpoints 404'd: `getChecks` now reports
  `unknown`, `isGreen` refuses it, and `mergePull` says so. A guard that reads
  silence as success is not a guard.
- **A repo with no CI at all counts as green.** Most of the portfolio is static
  PHP with no workflows; the alternative is a Merge button that never works.
  Documented at the top of `lib/github/checks.ts`.
- **`claude/*` branches do not link to work items** unless the PR title carries
  the `[coachme:<slug>]` marker. Anton opens `claude/*` branches constantly for
  unrelated work; linking them would make the desk's state fiction.
- **A write target that has no write scope degrades to `copy`** rather than
  failing the tap — nothing reached GitHub, so the item is still dispatchable by
  hand, and the reason is stored on the item.
- **Owner steps can only be copied**, never committed or opened as issues.
- **Proposals never earn a push on their own**; they ride in the digest body.
- **`migrations/0004` is outside this phase's Owns** — the two new rung names
  need the `nudges.type` CHECK widened, and a new nudge type that the database
  rejects is not a rung. Recorded here rather than done quietly.

## Known issues

  Postgres (approval gate refuses, dispatch records the audit row, status moves
  to `dispatched`, the one-liner matches `promptPathFor`), the repo-file and
  issue paths against a mocked API, and the write guard's refusals against a
  mocked GitHub. Run one real dispatch against a scratch repo when the PAT lands.
- **The watcher Routine was not created and lane 2 was not spawned** — both are
  Anton's to authorise (they cost sessions). The phase is otherwise complete.
- **`prompts/_watcher.md` now keys phase state off `docs/log/<id>.md` first**,
  because O3 and O4 both ran on harness-assigned `claude/*` branches rather than
  `phase/<id>`; a watcher that only looked for `phase/*` would have re-spawned
  finished phases.
- **The scan's per-repo cost grew**: a repo with work in flight now costs two
  more PR listings plus one check-runs call each. Still inside the 5-repo cap and
  the serverless timeout, but S7's bulk scanning should watch the rate limit.
