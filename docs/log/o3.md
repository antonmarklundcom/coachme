# O3 — Launch model, generator, ranking

Merged from `claude/eloquent-clarke-gbhd4a` (the session's designated branch;
the phase's own `phase/o3-launch-model` name was overridden by the session
instructions, which is the only deviation from the prompt's phase rules).

## Built

- `migrations/0003_launch_desk.sql`: stage + 9 revenue/evidence columns on
  `repos`, `work_items`, `dispatches`, `revenue_checks`, and `settings`'
  `weekly_report` / `github_write_ok`. Applies clean on Postgres 16.
- `lib/domain.ts`: `STAGES`, `REVENUE_MODELS`, `CURRENCIES`, `PAYMENT_RAILS`,
  `WORK_*` vocabularies, `WorkItem` / `Dispatch` / `RevenueCheck` types,
  `stageGap`, and the dispatch names (`branchFor`, `promptPathFor`,
  `oneLinerFor`, `toSlug`) that O4's write guard will be pinned against.
- `lib/launch/stage.ts`: evidence rules — raise only on evidence, one rung per
  run, never lower, `marketed` unreachable automatically.
- `lib/launch/items.ts`: the status machine; every illegal move throws.
- `lib/queries.ts`: work items, dispatch records, `setStage`, `patchRevenue`,
  revenue checks, `setWeeklyReport`, `setGithubWriteOk`, and `getQueues().money`.
- `lib/generate/`: `prompt.ts` (the mandatory header + the generator request),
  `sanitize.ts`, `templates.ts`, `run.ts` (`generateForRepo`).
- `templates/prompts/`: `finish-feature.md`, `owner-step.md`, `index.json`.
- `lib/score.ts`: `moneyDistance` and `moneyQueue` (D-H); `npm run queue` now
  prints stage and distance, closest-to-money first.
- `scripts/seed.ts`: stages and revenue models, non-destructively.
- Tests: `tests/launch.test.ts` (22), `tests/generate.test.ts` (18), 6 new
  ranking tests in `tests/score.test.ts`. Suite: 192 vitest + 130 legacy.

## Decisions

- **A repo with 3 untouched proposals gets no new ones.** §2 only blocked
  re-proposal while an item was in flight, so an un-approved repo would have
  burned a Sonnet call every scan re-proposing the same work. §2 updated in this
  PR rather than diverged from quietly.
- **`stage_suggestion` is returned, never written.** A stage raise needs
  evidence; a model's opinion is not evidence. The scan (O4) stages repos.
- **The header is prepended by us, not asked for.** The branch name and PR
  marker are how the scan finds dispatched work again; a model-authored branch
  name would be work the app can dispatch and then lose.
- **`model` is corrected, not dropped.** Anything that is not `opus`/`sonnet`
  becomes `sonnet` — dropping it would hand the cost decision to a default
  elsewhere (plan §4.8, `fable-cost-guardrail`).
- **Owner items get a human one-liner**, not `Read prompts/coachme/…`: nobody
  pastes an owner step into Claude Code.
- **The seed never re-stages a repo that already has evidence**, so `npm run
  seed` stays safe to re-run after the app has been staging repos for weeks.
- **`moneyQueue` excludes `infra` / `internal` repos** — the five tools will
  never earn directly, and parking them at the bottom of a money list forever
  is noise.

## Known issues

- **No repo seeded to `live`:** every `live_url_ok` in the 2026-08 baseline is
  null, because v2 never ran a real scan. 53 repos seeded 42 `building` / 11
  `deployable`. The first real scan after P0 will raise the live ones; S7's
  refresh is where this becomes visible.
- **The model call itself is unverified against the real API** (no
  `ANTHROPIC_API_KEY` in this environment). `generateForRepo` was run end to end
  against the real Postgres with the model round-trip stubbed at its `ask` seam:
  3 `proposed` rows on `besikt`, every `prompt_md` starting with the mandatory
  header, the cap holding at 3, the re-run refusing to add more. The keyless path
  throws `GeneratorUnavailable`, which the scan downgrades. Verify once P0 lands.
- **`templates/prompts/index.json` is read from disk at runtime.** On Vercel,
  Next's output file tracing may not include it, in which case the library
  degrades to empty and the generator simply has less to imitate. S4 should
  confirm on the deployed app and, if it is missing, add an
  `outputFileTracingIncludes` entry for `templates/**`.
- **`scripts/legacy/test/runbook.test.js` was edited outside this phase's Owns**
  (one test, made recursive) because `templates/prompts/` is a subdirectory and
  the old loop read it as a file. `tests/momentum.test.ts` likewise gained the
  new `Repo` fields to keep `tsc` green. Both were unavoidable; nothing else
  outside Owns was touched.
